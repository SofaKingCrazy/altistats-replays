# Altistats Replay Sorter — Daily-Updating Website

This is the existing V5 viewer, reorganized as a deployable static website for **GitHub Pages**. It contains your 9,190 archived matches, original date/duration/map/team/score filters, **highest/lowest combined-score sort**, direct replay links `https://www.altistats.com/viewer/?f=UUID.pb`, and credits to **Magnetic Duck — Altistats.com** and **Van1shing — planeball.com**.

## Publish the website

1. Create a **public** GitHub repository named `altistats-replays` with branch `main` at https://github.com/new. Do **not** commit a README on the creation screen, because this package already includes one.
2. Unzip the downloaded package. Use **GitHub Desktop** to publish the *contents* of the `Altistats_Daily_Website` folder to your repository (include the hidden `.github/workflows` folder). Alternatively, from within the extracted folder run:
   ```bash
   git init
   git add .
   git commit -m "Initial Altistats replay website"
   git branch -M main
   git remote add origin https://github.com/YOUR-USERNAME/altistats-replays.git
   git push -u origin main
   ```
3. In the repository open **Settings → Pages → Build and deployment → Source → GitHub Actions**. GitHub Actions will deploy the initial archived site after the push.
4. Open **Actions → Altistats daily update and site deploy → Run workflow** to attempt the first fresh import now. Scheduled runs attempt an import daily at **11:17 UTC**, then publish the updated site.
5. Your URL will be `https://YOUR-USERNAME.github.io/altistats-replays/` after GitHub Pages finishes its first deployment.

> **Important upstream limitation:** We confirmed the public Altistats site lists current games and archives, but could **not verify a documented API nor access a JavaScript-rendered match list from this environment**. The included Playwright collector is instrumented to watch live network responses, navigate recent calendar days, and extract **only complete** match records. It **has not been verified against the live browser rendering**. A failed import **never destroys** the 9,190 existing games; GitHub Actions will mark the update as failed and upload diagnostic files that can be used to tune the extraction logic. Do not interpret a scheduled trigger by itself as proof that fresh games were imported.

## Files

- `index.html`: the same V5 UI, with the game data loaded from an external file instead of a giant embedded array.
- `data/matches.json`: all archived games, de-duplicated by replay UUID.
- `data/matches.js`: data file loaded directly by the static website (generated by the updater).
- `data/status.json`: update metadata written after a successful new collection.
- `scripts/update_games.py`: Playwright collector for Altistats, strict validation, de-duplication, fails closed on extraction problems.
- `.github/workflows/daily-update-and-deploy.yml`: publishes on pushes and runs collector + deploy on the daily schedule or manually.

## How to check if the update is really working

Open **Actions** and click the latest scheduled run. The `Import new games from Altistats` step should say `Extracted X complete games; Y new; total Z`. Only then has the archive been refreshed. In the site, the top-right status should also show the last refresh date. A red run means the collector couldn't verify a fresh feed. Select the failed run's `altistats-collector-diagnostics` artifact to help us fix it.

## Troubleshooting

- **GitHub Pages initial URL shows 404:** check Settings → Pages and confirm Source = **GitHub Actions**; also look at Actions for the deployment run.
- **The new game count never increases:** review the scheduled workflow; Altistats' frontend or response schema may differ from those the collector recognizes. The archived viewer remains functional.
- **Workflow fails on permissions:** in Settings → Actions → General → Workflow permissions, allow GitHub Actions to have read and write repository permissions. For public repos, Pages also requires Pages to be enabled in repository settings.
- **No active daily runs after a long period:** GitHub can disable scheduled Actions on inactive public repositories. Re-enable in Actions. GitHub may delay or skip scheduled runs, so 11:17 UTC is approximate.
- **Privacy and courtesy:** the importer reads only publicly displayed match metadata, not replay binary contents; it never attempts to log in. Please respect site-owner usage policies and rate limits.
